# 小鱼缸（MyGo 独立原型）

桌面小组件：一块竖向透明玻璃/亚克力板，落在 menthe 浅蓝底座上；板内是高清等宽字符鱼 `><(((o>` / `<o)))><`、`o`/`O` 气泡、底部亮绿 `{~` / `~}` 水草。指针进入**板顶上方**标有 `FEED` 的细条后会先短暂亮起，停留约 0.2 秒后按指针的水平位置缓慢落下食物，移出即停；路过不会误投。点击或按住仍可一次或连投，并优先于悬停投食。小鱼用嘴（字符前端）追食，并显示约 1.3 秒的 `chomp` / `crunch` / `gulp`。吃食后会略微长大，到顶后不再追食，之后可能无性繁殖或衰老死亡，数量维持在大约三条。底部水草只是装饰，鱼可以从中游过并吃到附近的食物。未吃完的食物约 16 秒后淡出，不会瞬间清空。鼠标在**缸面上**停留时，每条鱼按自己的稳定性格反应：好奇的鱼轻轻靠近观察，胆小的鱼拉开距离，移开后平滑恢复闲游（不会每帧随机切换）；缸面悬停不会投食，也不会打断随后在上方条上的投食。板面默认**没有填充**（可透出壁纸）；窗外空白处的点击穿透仍待实机确认。**没有**圆缸、水面或沙石。

外观依据是参考视频的静态帧（工作副本 `/workspace/mygo-fish-reference/user-fishbowl.mp4`；实现时未观看该视频）。这是软件原型，**不是完整成品**，也不是硬件复刻。

默认鱼缸内容约 315×390（原先 420×520 的 75%），窗口四周另有约 16 DIP 透明边距，让边缘拖拽落在系统无边框窗口外侧约 5 像素的原生缩放拦截带之外。可拖拽鱼缸边缘或角落按比例缩放，也可在设置里用滑块调节（约 35%–125%）；两种方式共用同一个尺寸并会记住。默认锁定长宽比，100% 为原先内容大小。字符按当前大小和设备 DPI 重新栅格化，不用把低分辨率截图拉伸。缩到 35% 时，成鱼字符会保持单行可读（不再加粗，描边按比例缩小），不会把最小尺寸抬回 55%；75% 默认外观不变。设置窗口是独立尺寸，不会跟着鱼缸缩小到难以操作。

板面曾一度像浅蓝实心牌，原因是 MyGo 的 `ui.RGBA` 透明度参数是 **0–1**，当时误传了 0–255（例如 28），被夹成完全不透明。现已去掉正面填充，只保留细边线、右侧/顶部少量厚度和高光；其它半透明色已改为 0–1。

## 运行（Linux 验收二进制）

```sh
/workspace/mygo-fish-artifacts/mygo-desktop-fish-linux-amd64
```

或在项目目录：

```sh
cd /workspace/mygo-desktop-fish
go tool mygo dev
# 或
go run .
```

需要 Go 1.27.3 或更新版本。

- 指针停在板**上方**标有 `FEED` 的细条上：条会先短暂亮起，停留约 0.2 秒后按指针的水平位置缓慢投食（约每 300ms 一颗），移出即停；只是路过、尚未停稳时不会出食。短按仍会在松开时投一颗；按住超过 300ms 后大约每 200ms 连投，并优先于悬停投食。松开、失焦或移出投食条会停止。同时最多 8 颗食物。同一落点附近的连投会略微错开，避免完全叠在同一像素。点击缸面或底座、以及在缸面上悬停，都**不会**生成食物。左右贴边和落底的食物应能被吃到；未吃完的食物约 16 秒后淡出（不是一次性清空）。
- 指针停在缸面上：好奇的鱼靠近并看着指针，胆小的鱼受惊游开，保持安全距离后停留；同一条鱼性格稳定，不会每帧换反应。移出后平滑恢复闲游。这与 FEED 区的悬停投食不是同一件事。进食、出生及死亡动画优先，衰弱的鱼反应速度也会更慢。
- 按住**浅蓝底座**尝试拖动（标签 `DRAG`），与边缘缩放分开：只有底座内部会移动窗口，边缘和角落用来改大小。右键底座，或点击底座右侧 `SET`，或按 **Ctrl+Alt+G**（macOS 为 **⌘⌥G**）打开设置（玻璃质感与鱼缸大小）。托盘菜单里也有同一项，但本机 Linux 面板上托盘通常不可见，不能只靠托盘。
- 拖拽鱼缸的边缘或角落可等比缩放（35%–125%），指针会变成对应的缩放光标；松开或窗口失焦后停止并记住大小。设置里的滑块会跟着变，也可以只在设置里改。这是应用自己处理的拖拽缩放，不是系统窗口的自由拉伸（无边框窗口保持 `DisableResize`，以免被拉变形）。

## 键盘

- **Esc**、**Ctrl+Alt+I**（macOS 为 **⌘⌥I**）：无条件恢复交互（不会再打开穿透）
- **Ctrl+Alt+T**（macOS 为 **⌘⌥T**）：切换鼠标穿透
- **Ctrl+Q** 或 **Ctrl+Alt+Q**：退出

- **Ctrl+Alt+G**（macOS 为 **⌘⌥G**）：打开玻璃设置

全局快捷键与上面相同。Wayland 上可能要门户确认或因缺少 `.desktop` 而失败。代码将输入区域限制为投食条、板和底座，但窗外空白点击穿透尚未实机确认；要点到板后的桌面元素需打开穿透。

## 设置

默认为**真透明**（正面无填充，桌面透出）。如果在浅或深的桌面上不好辨认，可以手动调节，不必改外形：

- **真透明**：无填充，只保留边线和高光
- **浅色底** / **深色底**：给板面一层可调的浅或深色 tint
- **自动**：跟随系统浅色/深色外观（`mygo.Theme.IsDark` / `OnUpdated`）。深色系统用浅色 tint，浅色系统用深色 tint，便于看见轮廓。**这不是壁纸感知或屏幕取色**，也不会申请截屏权限。
- **玻璃透明度**：0–100%，0 为无填充，100% 为该预设下不透明
- **边缘高光**：0–100%
- **鱼缸大小**：35%–125% 的等比缩放，默认 75%。可用设置滑块，也可以拖拽鱼缸边缘或角落；数值实时同步并会记住。投食条、悬停、底座拖动和输入区域会跟着变。可用“恢复默认大小”。放大时会尽量保持窗口仍在屏幕工作区内。最小尺寸时投食条和 SET 会单独加大点击区，不拉伸缸面；成鱼字符保持单行可读，75% 默认外观不变。原先已保存的 55% 设置仍按 55% 打开。

从浅/深/自动切回真透明时，透明度会被设为 0。从真透明改到其它预设且透明度接近 0 时，会先升到约 18%，以便立刻看见效果。设置保存在应用数据目录的 `settings.json`（Linux 上一般是 `~/.config/小鱼缸/settings.json`）。自动模式只在应用就绪后读取系统主题；若当时读不到，设置窗会说明，并暂按浅色桌面处理，手动预设仍可用。

## 生命周期

开场仍是三条成鱼，外形与原来的 `><(((o>` / `<o)))><` 相同。吃食后身体会略微长大，到达上限后不再追食。达到上限一段时间后，按种群数量做一次随机判定：缸里少于三条时更常出生，多于三条时更常进入老年死亡，以此把数量保持在三条附近（最多 5 条，至少 1 条）。出生时成鱼先短暂停住，身体轻微鼓起（只是绘制缩放，不会改变窗口），再从体侧滑出一条更小的鱼，落在附近并留在玻璃内。刚滑出时没有字符（孵化感），随后先出现 `o`，再随体长逐渐补全，成鱼仍用原来的整段字符。老年死亡会翻白（肚皮朝上的字符）并慢慢上浮淡出。不同鱼的游速和颜色有轻微差别；接近死亡前会游得更慢、字符更淡。幼鱼会初始化自己的稳定性格；出生滑出、衰老死亡期间不会被玻璃互动打断，缸面悬停不会投食。

## 已知问题（不阻挡本版外观与投食）

- **角落堆积（已在本版改代码并经单元测试）**：此前用鱼身中心（半宽 54）对半径 28 判定吃食，贴左右壁落下的食物够不到，连投后会堆在角落，三条鱼沿该侧纵向挤在一起。现改为嘴部追食，鱼可进入水草带（水草本就没有碰撞体，但原先把 `PlantY` 当成游动底板）。894b99b 的 Linux 实机录屏显示未持续堆角和穿水草；肉眼不能可靠区分底部逐食物捕食与 TTL。新增默认关闭的 food trace 和同生产 `Tank.Step` / `Feeder` 测试，逐 ID 记录生成、消费鱼 ID/时间或超时原因；用 `FOOD_TRACE_OUT=/tmp/food-trace.json go test ./tank -run TestFoodFateScenarios -count=1` 可复验贴墙落底、水草和长按松开（含全部先落底再开始鱼动），断言真正消费、零超时、无残余锁。旧视频仍标原提交，不冒称新提交演示。
- **玻璃设置原生验证未完成**：894b99b 的补拍录屏 `settings-proof.mp4` 损坏（缺少 moov），录制及鱼缸进程均已不在，运行日志也未留存，不能确定退出原因或宣称设置实机验收通过。对报告的深色→透明度59%→高光80%→浅色→真透明→高光30%操作，生产设置视图的 headless 测试可完成且不会请求 quit；这不能替代原生窗口稳定性验证。另复现了原340高设置窗“关闭”按钮位于窗外的问题，已将高度增至可容纳玻璃与大小控件并验证可点击；该次退出原因当时未查明。本版在 Linux 上已修复“打开过设置后再关主窗口会取消退出”的问题，关闭主窗口应结束进程并回到终端。
- **窗口移动（Linux）**：在本机多次实测中，官方 `DragWindow()` 和随后的 `Window.SetPosition` 跟随指针**都未能移动**这个透明无边框窗口。底座拖动仍可能受到这一限制。可见缸壁和角落的边缘缩放、设置滑块改大小，以及关闭主窗口后进程退出，已在本机 Linux 上复测通过。这不能类推为 macOS 或 Windows 的拖拽手感，那些平台仍待实机确认。
- **托盘**：已装 `libayatana-appindicator3-1`，但本机 `xfce4-panel` 没有 systray/StatusNotifier 插件，会话总线也没有 `org.kde.StatusNotifierWatcher`，面板上仍可能无图标。当前桌面未提供托盘支持，不能作为本机已验收功能。Linux 上关闭主窗口应退出进程（即使 NewTray 成功），以免窗口消失后终端还挂着进程。
- **最小尺寸字符（已在本版修复，Linux 实机看过）**：缩到 35% 时，成鱼曾因过小加粗和偏粗描边挤在一起，朝左的 `<o)))><` 会拆开或错位。现已保持 35% 下限，成鱼字号取整并至少 9 DIP，小于 12 DIP 不再加粗，描边按比例缩小，并禁止折行。Linux 上把鱼缸缩到 35% 后，朝左成鱼可读成一行完整字符；旁边单独的 `o` 是幼鱼或气泡，不是被拆开的部件。这不能代替 macOS 或 Windows 上的实机字体核对。
- **macOS 打开（preview.1）**：从 GitHub 下载的 zip 在 macOS 上可能提示“小鱼缸.app 已损坏，无法打开。你应该将它移到废纸篓。”这通常不是文件损坏，而是交叉编译包只有链接器级签名（或完全无签名），Gatekeeper 在带隔离属性时会这样提示。preview.2 起改为在官方 macOS runner 上对整个 `.app` 做 ad-hoc 包签名，并用 `codesign --verify --strict --deep` 校验。**这不是 Developer ID，也不是公证**，仍可能出现“无法验证开发者”之类提示，可在系统设置的隐私与安全性中选择仍要打开。需要 macOS 13 或更高版本。
- **Windows 安装（preview.1）**：该版本只提供 zip，没有 Setup。preview.2 起由 MyGo 的 NSIS 生成 `myfish-setup-<version>-<arch>.exe`：当前用户目录安装（无需管理员）、开始菜单快捷方式、完成页可选桌面快捷方式、系统设置中可卸载，默认不开机启动。安装器未做可信代码签名，SmartScreen 可能报警，这不是不提供安装器的理由。
- macOS / Windows 上的透明、投食、悬停、拖动和托盘交互仍以各平台实机证据为准，不能用交叉编译成功代替验收。

## 安装包

正式安装包由 GitHub Actions 在官方托管 runner 上构建，产物作为 workflow 工件上传，再按版本发布：

- macOS 13+：在 `macos-latest` 上构建 `.app` / `.dmg`，整包 ad-hoc 签名并 `codesign --verify --strict --deep`。不是 Developer ID，也未公证。
- Windows：在 `windows-latest` 上构建 `myfish-setup-0.1.0-amd64.exe` 与 `myfish-setup-0.1.0-arm64.exe`（MyGo + NSIS，不是 zip 改名）。安装到 `%LOCALAPPDATA%\Programs\MyFish`，无需管理员；开始菜单会创建快捷方式，完成页可选择桌面快捷方式；静默安装 `/S` 不创建桌面快捷方式。卸载程序会出现在系统设置中。默认不会写入开机启动。amd64 安装器会在该 runner 上做安装、短暂启动和卸载；arm64 安装器会构建，但不会在 amd64 runner 上执行安装。

```sh
gofmt -w .
go test ./...
go vet ./...
# Linux 开发构建：
go tool mygo build -platform linux/amd64 -o dist
```

源码仓库：[ybbapp/myfish](https://github.com/ybbapp/myfish)。

## 玻璃互动验收候选

本轮已实现此前留到下一主要版本的真实玻璃互动：开场三条鱼保证包含好奇和胆小两种性格，随种子确定并稳定保留；幼鱼也初始化自己的性格。鱼会平滑靠近或远离指针，缸面坐标仍使用设计空间，35%–125% 缩放不会改变反应距离的比例。进食优先，出生和死亡动画不会被打断。不新增全局输入拦截。

流水线新增了挂载 DMG 后的整包签名与最低系统版本核对、Gatekeeper `spctl` 诊断、宿主架构实际产物的短暂启动；Windows 新增 Authenticode 状态、卸载注册及自启注册检查，升级基线改为 preview.6。这些新增检查尚待下一次官方 CI 执行，不是已完成的验收结果。ad-hoc 不等于 Developer ID 或公证，SmartScreen / 浏览器下载后的 Gatekeeper 放行仍未获验证。
